# Wi-Fi Relay 1.0.0-17 release candidate

This candidate combines the standalone service and settings app with optional
GNOME Shell and desktop tray packages. Desktop clients share one authorized
controller. The create_ap backend remains the default; the native NetworkManager
AP+STA backend and downstream desktop patches remain explicitly experimental.

## Reliability and security changes

- Privileged logs, locks, and legacy backend state use private service-owned
  runtime directories, rather than predictable shared `/tmp` files.
- The legacy controller checks its private PID marker and process command before
  reporting a session; Stop targets that PID, leaving independently started
  hotspots alone. Service shutdown stops its owned session.
- Worker events have size and per-poll read limits. Invalid messages, activation
  timeouts during automatic recovery, and stalled suspend shutdowns receive a
  bounded SIGTERM grace period followed by SIGKILL and ownership recovery.
- DHCP and DNS runtime firewall rules apply to the hotspot interface. Startup
  leaves permanent firewalld configuration and AppArmor enforcement intact.
- Client polling uses DHCP names without blocking on reverse DNS. Poll failures
  are logged without repeating the same error on every poll. Malformed deeply
  nested preference files fall back to defaults.
- Core dependencies explicitly include Bash, util-linux, and sysvinit-utils.
- Debian archive timestamps are normalized for reproducible binary builds, even
  when a supplied source epoch is in the future. NetworkManager recovery checks
  interface identity again after profile deletion before removing an interface.

## Installation and rollback

Install the main package and only the desktop controls you want. The optional
packages require exactly the same version as the main package. No replacement
NetworkManager, GNOME Settings, or network applet package is required for the
standalone GUI and the default backend.

Stop active sharing before upgrading, particularly an older create_ap session:
this candidate deliberately does not adopt legacy shared `/tmp` state. Upgrades
preserve configured credentials and preferences. Fresh installations generate
an individual random password.

Keep the previous three matching packages and back up `/etc/wifi-hotspot.conf`
with owner-only permissions before upgrading. To roll back, stop sharing, install
all previously used packages together with `apt install --allow-downgrades`, and
restore the private configuration only if required. Verify status and forwarding
before connecting clients. Removing an optional integration leaves the service,
standalone editor, and credentials intact.

If a locally enforced dnsmasq AppArmor policy denies the new runtime paths,
review the denial and grant only the required files under
`/run/wifi-relay/create-ap/` in the administrator's local policy. Relay does not
weaken or replace that policy. Do not switch the entire profile to complain mode.

## Stable-release gate

Automated package and widget checks do not certify wireless hardware. Before
publishing this candidate as stable, validate this exact build on the supported
adapter/driver and desktop combinations: DHCP/DNS and verified HTTPS traffic,
multiple clients, repeated start/stop, upstream loss and recovery, radio-off,
suspend/resume, service crashes/restarts, and extended operation. Record AppArmor
and firewall behavior where those policies are enforced.

Earlier Beta 2 hardware evidence is available in
[the live validation report](../networkmanager-live-validation.md). It describes
an earlier build on one driver and must not be presented as validation of this
candidate. GNOME Settings and applet replacement packages have their own version
and hardware gates. No PPA upload or community announcement is part of this
candidate preparation.
