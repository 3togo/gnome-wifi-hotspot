# Wi-Fi Relay 1.0.0-31

**[Download bundle.deb — recommended](https://github.com/3togo/gnome-wifi-hotspot/releases/download/v1.0.0-31/bundle.deb)**

A daemon reliability update for Ubuntu 26.10 (Stonking). The bundle includes
settings, the service, GNOME controls and tray controls; GNOME Shell is optional.
The stable default is create_ap. **Native NetworkManager AP+STA and downstream
integration patches remain experimental.** This release does not promote them.

## Changes

- Serialize privileged backend operations while keeping D-Bus status and Stop
  responsive. Stop cancels startup even before an instance PID is published.
- Recover owned children, interfaces, firewall rules and instance state after
  crashes. Preserve unrelated firewall rules and restore physical adapter
  management only when Relay changed it. Report incomplete cleanup as an error.
- Validate process identity and use pidfds before stopping children. Defer AP
  stop signals during mutex bookkeeping to avoid cleanup deadlocks.
- Ignore stale asynchronous settings loads after retries or service changes.
- Respect `DPKG_ROOT` during offline package assembly without altering host
  services or detecting host adapters.
- Provide a bounded administrator-session helper for physical tests, including
  retries and cleanup, without storing passwords or weakening authorization.

## Downloads, upgrade and rollback

Download `bundle.deb`, or the matching `gnome-wifi-hotspot`,
`gnome-wifi-hotspot-gnome` and/or `gnome-wifi-hotspot-tray` packages at `1.0.0-31`.
The versioned bundle is identical to `bundle.deb`. Install either the bundle or
separate layout. APT supplies distribution dependencies; no replacement
NetworkManager, GNOME Settings or applet package is required.

Download [SHA256SUMS](https://github.com/3togo/gnome-wifi-hotspot/releases/download/v1.0.0-31/SHA256SUMS)
into the same directory and verify every downloaded file:

```bash
sha256sum --ignore-missing -c SHA256SUMS
sudo apt install ./bundle.deb
```

Stop sharing before installing. Keep an owner-only backup of
`/etc/wifi-hotspot.conf` and the previous matching packages. Upgrade all installed
Relay packages together. Configuration, credentials and preferences are retained;
sharing does not resume automatically after installation. Log out and back in
after installing GNOME controls if the extension is not loaded.

To roll back, stop sharing and install the saved bundle, or all saved matching
separate packages together, with `sudo apt install --allow-downgrades ...`.
Avoid purge to retain configuration. Per-user preferences are retained.

## Validation and provenance

The final runtime payloads are compared against the physically tested
`1.0.0-31~fix7` packages from runtime commit `39df665`. Final release changes
update version metadata, documentation and packaged evidence. The historical
candidate versions, hashes, failures and restoration results are not rewritten
as final-package physical tests. `VALIDATION.json` records the release commit,
source tree, package hashes, executed final checks and CI; `SHA256SUMS` covers
all supplied assets except itself. Debian source artifacts and build metadata
are included. Artifacts are unsigned; no signed APT repository is established.

- 383 Python unit tests, Node tray checks, private D-Bus integration, real GTK
  widgets and extracted-package checks cover the final source and packages.
- Source/binary builds, sanitized applet checks, isolated GNOME Shell checks,
  and disposable-container installation, upgrade, layout-switch, removal and
  purge checks cover release packaging. Lifecycle checks preserve credentials
  and generate secure defaults for fresh installations.
- [Physical fault trials](../evidence/physical-wifi-daemon-fixes-2026-10-19.json)
  used an Android 14 phone and tablet over USB ADB, one Intel/iwlwifi AP driver,
  and a separate mt7601u USB Wi-Fi upstream with Ethernet disconnected.
  Both physical and virtual AP modes obtained fresh DHCP leases and completed
  verified HTTPS to two hosts; invalid TLS was rejected. Six startup-cancellation
  timings (0–1.8 seconds) and recovery after killing the AP shell passed without
  owned children, interfaces, rules or instance directories left behind.
- The [installed 2.4 GHz check](../evidence/physical-installed-2.4ghz-2026-10-19.json)
  verified channel 12 (2467 MHz), Stop/Start, fresh DHCP, HTTPS and invalid-TLS
  rejection on both clients. That cohort retained Ethernet as its Internet
  uplink. Credentials were preserved, one administrator session was closed,
  Android power settings were restored and temporary helpers were removed.

## Testing limits and retained observations

The physical host ran kernel `7.2.6-070206-generic` and downstream NetworkManager
`1.58.1-1ubuntu3+relay1+dev3`. This cohort does not establish physical behavior
with stock NetworkManager; stock Ubuntu 26.10 packages are covered by CI.
Fault injection used an administrator caller through the production D-Bus API,
so it does not establish physical desktop-user authorization coverage.

Earlier candidates failed startup cancellation and mutex cleanup; their results
remain in the [development record](1.0.0-31-development.md) alongside the fixes
and successful final candidate. Strict NXDOMAIN expectations returned
NOERROR/NODATA; independent queries for the same generated names bound to the
upstream address matched. Failed strict assertions and passing comparisons
remain separate, including in the installed 2.4 GHz record.

This revision does not complete the ten-cycle hardware matrix, other AP drivers,
other client OS families, natural roaming, multi-adapter failover, reboot/suspend
fault trials, native-backend physical recovery or extended multi-client soaks.
Channel 12 is not evidence for arbitrary 2.4 GHz clients or regions; channels
must be permitted by the local regulatory domain and supported by both clients
and the driver. A channel preflight refusal is not successful AP validation.

Physical host GDM/login and hardware graphics, RPM installation, other Ubuntu
releases and other distributions remain outside the validated scope. Earlier
GNOME/XFCE container-login records retain their own build and environment;
they are not new revision-31 physical results.
