# Development validation — 19 October 2026

The final tested development build is `1.0.0-31~fix7`, with runtime source at
`39df665`. This is unpublished development evidence; revision 30 remains the
published baseline. Exact package and runtime hashes, individual results, and
the preceding failures are in the
[physical test record](../evidence/physical-wifi-daemon-fixes-2026-10-19.json).

| Check | Final result |
| :--- | :--- |
| Python unit tests | 375 passed, including actual process cancellation and signal injection during mutex bookkeeping |
| Private D-Bus integration | 11 passed; Node tray tests also passed |
| Physical and virtual AP modes | Android 14 phone and tablet matched the current BSSID and obtained fresh DHCP leases in both modes |
| Client traffic | Both clients completed verified HTTPS to two external sites and rejected an invalid TLS hostname in both modes |
| Startup cancellation | Six timings from 0 to 1.8 seconds passed; D-Bus remained responsive and no owned children, interfaces, rules or instance directories remained |
| Shell-crash recovery | Stop cleaned up after the AP shell was killed |
| Unrelated state | Existing firewall rules and IP forwarding setting were retained |

One final strict NXDOMAIN assertion failed because the gateway returned
NOERROR/NODATA. A separate query for the same generated name, bound to the
upstream Wi-Fi address, returned the same result. The failed strict assertion
and passing comparison are recorded separately.

Earlier candidates failed and remain in the record. `fix5` missed Stop before
startup registration, leaving an instance and eight firewall rules. Commit
`9c39d5d` tracks the shell directly and signals its verified identity through a
pidfd. `fix6` then exposed a mutex bookkeeping interruption that left an interface
and instance directory. Commit `39df665` defers signal-triggered exit until
bookkeeping releases its descriptor. The final build passed the affected cases.

The bench used one Intel/iwlwifi AP driver and a separate mt7601u USB Wi-Fi
upstream, with Ethernet disconnected during traffic checks. Both clients used
USB ADB and were kept awake and unlocked. Administrator D-Bus calls controlled
the fault tests; this does not establish physical desktop-user authorization
coverage, another AP driver, another client OS family, native-backend recovery,
reboot/suspend behavior, the ten-cycle release matrix, or an extended soak.

Cleanup restored the original revision 28 packages, all 57 original package
files, configuration, connection identities and route preference, tray startup
preference, and Android power settings. Temporary Android helpers were removed;
the daemon finished active, enabled and unmasked. A tray activation dialog caused
by the temporary maintenance mask is retained as a test-side observation. Older
published test records were not changed.
