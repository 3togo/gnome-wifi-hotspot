# Wi-Fi Relay 1.0.0 release maintenance

Stable release: `v1.0.0`; Debian revision: `1.0.0-18`; validated platform:
Ubuntu 26.10 (Stonking). See [release notes](../../RELEASE_NOTES.md) for changes
and [the user guide](../user-guide.md) for installation. The default create_ap
app is released as stable. Native NetworkManager AP+STA and downstream desktop
patches retain their experimental scope and hardware limitations.

## Upgrade and rollback

Stop sharing before upgrading, especially an older create_ap session that used
shared `/tmp` state. Relay does not adopt those legacy sessions. Install the
main and selected GNOME/tray packages at matching versions in one transaction.
Upgrades preserve credentials and preferences but do not resume broadcasting.

Before upgrading, keep your previous matching packages and back up
`/etc/wifi-hotspot.conf` using owner-only permissions: it contains credentials.
To roll back, stop sharing, use `apt install --allow-downgrades` to install all
previously selected packages together, and restore the private configuration
only if necessary. Verify status and forwarding before connecting clients.
Removing an optional integration leaves settings and the service intact.

If enforced dnsmasq AppArmor policy denies runtime files, inspect the denial and
grant only the required files under `/run/wifi-relay/create-ap/` in local policy.
Relay leaves enforcement and permanent firewall policy intact.

## Publication and evidence

Release downloads include the three split `.debs`, Debian source artifacts,
checksums, and a validation/provenance report. They are unsigned; GitHub release
publication does not establish a signed APT repository or PPA. Old beta binary
downloads are retired, while historical source tags and evidence remain.

Native checks cover unit tests, widgets, sanitized applet code, Shell 51 loading,
private-bus authorization, and source exports/builds. CI adds isolated package
lifecycle testing. The final build has not been certified for privileged live
wireless traffic, suspend/resume, multi-client soak, or enforced security-policy
faults. [Earlier hardware evidence](../networkmanager-live-validation.md) applies
to its recorded build, not automatically to this release. Test these scenarios
on deployment hardware before relying on unattended sharing.
